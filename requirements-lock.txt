# Exact environment, for reproducing a committed number.
#
# requirements.txt states what the model needs (floors, no ceilings) and is the
# right file for running the code.  This file states what was actually
# installed, and is the right file when the question is why a number came out
# the way it did.  These tables feed a paper; "numpy>=1.24" does not identify a
# result.
#
# Provenance
# ----------
# Everything in results/tables/ comes from the empirical rerun of 2026-08-21
# (docs/rerun_manifest.md).  The five packages that can move a number --
# numpy, scipy, pandas, scikit-learn, SALib -- are pinned below at the
# versions present in the environment that produced them.  All five were
# installed on or before 2026-05-20, three months before the rerun.
#
# The remaining entries are transitive plumbing (font handling, argument
# parsing, test-runner internals).  They are pinned because a lock file that
# pins only some of its inputs is not a lock file, but they were resolved fresh
# on 2026-09-05 and their versions differ from the original environment.  None
# of them touches a float.
#
# Install
# -------
#   python3.11 -m venv .venv
#   .venv/bin/python -m pip install --no-deps -r requirements-lock.txt
#   .venv/bin/python -m pip install --no-deps -e .
#
# --no-deps is required, not a convenience.  SALib 1.5.2 declares numpy>=2.0,
# so any resolving install upgrades numpy to 2.x.  The committed results were
# produced under numpy 1.26.4, and scikit-learn 1.2.2 is built against the
# numpy 1.x ABI and fails to import under 2.x.  With --no-deps pip installs
# exactly this list and never consults that constraint.  SALib runs correctly
# on numpy 1.26.4; the declared floor is wrong for our use, not the pin.
#
# Verified on 2026-09-05: under exactly this set, the full suite passes (577
# tests), including the golden regressions pinned to 1e-12 and the table
# regeneration check that compares serialized bytes.  No committed output was
# regenerated to produce this file.
#
